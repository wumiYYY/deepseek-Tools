# 在线升级与发布

1.4.7 起支持在线更新，首个版本仍需手动覆盖安装。之后在「我的 → 关于 → 检查更新」检查，启动后每天也会检查一次；有新版本才提示，确认后下载，最终由 Android 系统确认安装。

## 当前服务

- 更新地址：`https://161.118.233.45/whale-vault/update.json`。
- Nginx 为现有 HTTPS IP 站点增加独立 `/whale-vault/` location；其他服务路由保留。
- `/var/www/whale-vault/` 只存清单、正式 APK 和 SHA256，关闭目录列表；请求必须携带独立 `X-Whale-Update-Token`，缺少凭证返回 404。
- 凭证在构建机 `local.properties` 的 `WHALE_UPDATE_TOKEN` 中配置（64 位小写十六进制），编入 App，仅用于访问更新目录；不是服务器登录密码，不具备上传或管理权限。后续发布须保留此值，让旧版仍可下载更新。
- 现有 Let's Encrypt IP 短期证书由服务器 Certbot 定时续期及 reload hook 维护，不在 App 中关闭证书验证，也不固定短期证书。

## 后续发布

1. 修改 `app/build.gradle.kts` 中 `versionNameValue`，版本必须高于已发布版本。填写变更说明。
2. 构建机执行：

```powershell
.\scripts\release.ps1 -PrepareUpdate -UpdateNotes "本次更新说明"
```

此命令执行单测、正式签名构建及签名/包名校验，生成 `dist/<版本>/` 安装包和 `dist/publish/whale-vault/` 静态发布目录。更新说明由 JSON 序列化写入，支持引号和换行。

3. 使用 Python 3 + OpenSSH（系统自带 `ssh`）执行：

```powershell
python scripts/deploy-update.py
```

脚本默认使用系统 OpenSSH 配置中的身份认证，必要时由 SSH 交互询问密码，不保存在脚本中；首次连接记录主机公钥，后续校验已记录的公钥。SSH 只传小文件和执行命令，大 APK 通过临时 HTTPS 上传入口传输，传完立即关闭；入口仅允许独立凭证访问的单个随机路径和当前 APK，避免长期开放上传接口。需要使用有 `sudo -n` 权限的部署账户。首次接入 Nginx 时加 `--configure-nginx`；当前站点已配置后不再需要此参数。

上传采用显式文件列表：本次 APK、清单、安装脚本和临时更新访问配置。签名私钥、签名密码、AI Key 和 SSH 密码不上传。APK 先落盘，清单最后原子替换；拒绝发布更低版本，拒绝用不同 APK 覆盖已发布的同一版本。

构建机已设置 `HTTPS_PROXY` / `HTTP_PROXY` 时，发布脚本会让 HTTPS 传输和 SSH 控制连接使用该网络代理；这是构建机网络设置，不写入 App 或服务器。需要直连 SSH 时可设置 `WHALE_SSH_PROXY=0`。

## 客户端校验及失败处理

- HTTPS 校验服务器，更新下载不跟随重定向。
- 清单限制稳定渠道、有效版本及预期相对下载路径。
- 下载时校验长度及 SHA256，失败删除临时文件。
- 安装前检查包名、版本号、版本名称、原版证书和当前安装证书一致。
- 下载完成后保留在 App 缓存中，可以再次点击安装。首次允许「安装未知应用」后自动继续安装。
- 失败可重试，也可以继续从发布者处获得正式 APK 手动覆盖安装；不要求卸载或清空账本。

Nginx 首次配置前备份到 `/var/backups/whale-vault/<时间>/`，`nginx -t` 或重载失败时恢复原配置。签名私钥始终保留在本机构建机。
