## 0.1 交接包**只发一次**，之后靠 git 同步

这一点先说清楚，免得双方每发一版就手动传一次 17MB 的 zip：

| 东西 | 怎么同步 | 需要重新发包吗 |
|---|---|---|
| 代码 / 文档 / 规则表 | `git pull`（分支 + PR） | ❌ 不用 |
| 签名 keysotre + 三个口令 | **私密渠道，只发一次** | ❌ 除非换钥匙（正常永远不换） |
| `local.properties` | 同上，只发一次；`sdk.dir` 自己改成本机路径 | ❌ 不用 |
| 新版本 APK | 他自己用同一把钥匙打；或等更新服务器上线后从 `update.json` 拉 | ❌ 不用 |
| `update.json` / 服务器目录 | `scripts\make-update-json.ps1` 在**构建机**生成 → 同步到服务器 | ❌ 不用（这是部署动作，不是交接） |

判断标准很简单：**只有"秘密"需要私发，别的一律进 git**。
所以交接包本质上是一次性 onboarding 物料；`scripts\make-handover.ps1` 只是把它重新生成一遍
（改了文档想给对方一份最新快照时才用，里面的 `VERSION.txt` 会写明是哪个 commit / 哪个版本）。

## 1. 你必须拿到的四样东西

| # | 东西 | 从哪来 | 没有会怎样 |
|---|---|---|---|
| 1 | **仓库权限**（GitHub collaborator，建议 Write 而不是 Admin） | 仓库所有者邀请 | 只能在本地改，没法 PR |
| 2 | **`keystore/jingyuniang-release.jks` + 三个口令** | 私密渠道（不是 git） | 只能出 unsigned/debug 包，**盖不了已装用户** |
| 3 | **`local.properties`**（含 `WHALE_*` 口令 + 你的 `sdk.dir`） | 同上，或用模板自己填 | 构建日志会打印「缺少签名配置…产出 unsigned APK」 |
| 4 | （可选）**一个基线 APK**：`dist/<版本>/` 里任意一版 + `SHA256SUMS.txt` | 所有者私发或更新服务器 | 不影响开工：**证书指纹 `e7962e34…ef1975` 就是对照物**，自己打一个包跑 `apksigner verify --print-certs` 比对即可 |

口令（三个）：**不写在仓库里**，见你收到的私密交接包（`签名/local.properties` 或所有者当面告知）。

```
WHALE_STORE_PASSWORD = <SIGNING_PASSWORD>
WHALE_KEY_ALIAS      = jingyuniang      # ⚠️ 不是 whale
WHALE_KEY_PASSWORD   = <SIGNING_PASSWORD>
```

**装好之后第一件事**（10 秒，不做这步后面全是白忙）：

```powershell
.\scripts\setup-signing.ps1 -JksPath <你收到的.jks> -StorePassword <SIGNING_PASSWORD> -KeyPassword <SIGNING_PASSWORD>
# 成功标志：✅ 密钥库自检通过 + 「✅ 与正式版一致，出的包能覆盖安装老用户」
```

## 3. 你可以在他基础上做什么（正常动作）

```powershell
# 环境（项目自带工具链，不动系统）
.\scripts\build.ps1 -Task ":app:testDebugUnitTest"     # 120 个单测
.\scripts\build.ps1 -Task assembleRelease
.\scripts\release.ps1                                  # 测试→构建→dist/<版本>/

# CI 同款
$env:JAVA_HOME="$pwd\.toolchain\jdk17"; $env:ANDROID_HOME="$pwd\.toolchain\android-sdk"
.\gradlew.bat :app:testDebugUnitTest --no-daemon
```

- 分支：功能走 `feat/xxx` + PR；`main` 只放发版提交；**规则改动单独 commit**（最易冲突）
- 改抓取规则：`assets/capture_rules.json`，改完 `CaptureAllRulesTest`（逐条遍历 490 条）会兜底；
  用户侧还有「设置 → 数据导入导出 → 说人话的规则」可以直接加词
- 改数据库：`@Database(version=N+1)` + `MIGRATIONS` 加 `Migration(N,N+1)`，**永远不要**加回
  `fallbackToDestructiveMigration()`（那是静默清库，踩过一次）
- `scripts/*.ps1` **必须存成 UTF-8 with BOM**，否则 PowerShell 5 报「缺少右 }」

### 3.1 如果你想发**自己的**版本（不是覆盖他的用户）

两条路，**必须选清楚**：

| 方案 | 做法 | 后果 |
|---|---|---|
| A. 继续用原签名 | 用他的 jks 打包 | 你能覆盖老用户，**但你们发的就是同一个 App**，谁先发谁生效 |
| B. 独立发行 | **换 `applicationId`**（如 `com.yourname.whalevault`）+ 你自己的 keystore | 和老用户互不影响；**同包名换签名 = 永远装不上**，只能卸载重装 |

## 4. 服务器部署：只需要「静态托管 + 一个 json」，不需要后端

### 4.1 目录结构（建议）

```
https://<你的域名>/whale-vault/
├── update.json                       # 客户端只读这一个文件
└── 1.4.1/
    ├── jingyuniang-v1.4.1.apk        # ⚠️ 换成 ASCII 文件名，避免 URL 百分号编码踩坑
    └── SHA256SUMS.txt
```

生成方式（脚本已带，见 §4.4）：

```powershell
.\scripts\make-update-json.ps1 -PublishDir D:\publish\whale-vault `
    -BaseUrl https://files.example.com/whale-vault -Notes "修 4 处交互问题"
```

### 4.2 nginx 片段（关键就三条：禁缓存 update.json、给 apk 正确 MIME、关掉目录列表）

```nginx
location = /whale-vault/update.json {
    root /var/www;
    default_type application/json;
    add_header Cache-Control "no-store";          # ← 必须，否则客户端拿到旧版本号
}
location /whale-vault/ {
    root /var/www;
    types { application/vnd.android.package-archive apk; }
    autoindex off;                                # ← 别让历史包被列出来
    add_header Cache-Control "no-cache";
}
```

对象存储（OSS/COS/S3）同理：**`update.json` 的 `Cache-Control: no-store` 一定要单独设**，
其余文件可以长缓存（文件名带版本号）。

> 🔒 **别裸奔在公网**：至少加一层 HTTP Basic Auth / 签名 URL / 固定 token。
> 原因不是技术，是素材授权（见 §6）——公开可下载 = 公开分发。

### 4.3 `update.json` 字段（`docs/update.json.example` 是可直接改的模板）

```json
{
  "versionCode": 10401,
  "versionName": "1.4.1",
  "apk": "1.4.1/jingyuniang-v1.4.1.apk",
  "sha256": "0ede13c6…1c6c",
  "sizeBytes": 25770933,
  "signatureSha256": "e7962e34c241992bb69d781a6451390871bce3c26fb67a9b45dcac0558ef1975",
  "channel": "stable",
  "publishedAt": "2026-10-26T16:20:00+08:00",
  "minSupportedVersionCode": 0,
  "notes": "修 4 处交互；退款冲正更好用"
}
```

- `apk` 用**相对路径**，客户端按 `update.json` 的 URL 解析（换域名不用改 json）
- `sha256` **必填**，客户端下载后必须校验（见 §5）
- `signatureSha256` 可选但建议：客户端可以用它跟「已装包」的证书比对，一次性防住「野包」
- `minSupportedVersionCode` 用于强更（`0` = 不强制）
- `notes` 直接展示给用户，写人话

### 4.4 客户端在线更新（1.4.7 已实现，部署详见 `docs/在线升级.md`）

1. 关于页「检查更新」及启动后每天自动检查 → HTTPS GET `update.json`（`no-cache`，失败不影响手动安装）
2. `versionCode > BuildConfig.VERSION_CODE` 才提示；下载到 `cacheDir`（**要用户点，不自动下**，省流量）
3. 下载完**先校验 sha256**，不符直接删除并提示
4. 更稳一层：用 `PackageManager.getPackageArchiveInfo(..., GET_SIGNING_CERTIFICATES)` 读下载包的证书，
   跟 `signatureSha256` / 已装包证书比对 → 不一致就拒绝
5. `AndroidManifest.xml` 需要加 `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />`
   （1.4.7 已添加）
6. `res/xml/file_paths.xml` 的 `<cache-path name="cache" path="." />` **已经就位**，`FileProvider` 直接用
7. 拉起安装器：`ACTION_VIEW` + `application/vnd.android.package-archive`
8. **`versionCode` 只能升不能降**（覆盖安装要求 `>=` 已装版本）；回滚要「用旧代码打更高 versionCode」，不能降号

## 5. 红线（这几条踩了就是数据事故，不是 bug）

1. **签名不能换**。同包名换签名 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE` → 用户只能卸载重装 →
   账本全丢（除非事先导了加密备份）。所以：keystore 丢了就真的回不去了。
2. **keystore 不进 git、不进公开 CI Secrets、不上服务器**。`.gitignore` 已含
   `keystore/` `*.jks` `*.keystore` `*.p12` `local.properties`。
   要 CI 出正式包，用 tag 触发 + Repository Secrets（base64 存 jks）并接受「泄露面变大」，
   默认建议：**CI 只跑测试，正式包在受控机器本地打**。
   `app/build.gradle.kts` 已支持用同名**环境变量**覆盖口令，不必把口令写进任何文件。
3. **不要加回 `fallbackToDestructiveMigration()`**。迁移缺失就让它抛异常，数据文件还在，回装旧版还能用。
4. **更新包必须校验 sha256**；服务器能改 `update.json` 的人，就能给所有人推包 —— 所以别把
   「谁能写那个静态目录」当小事。
5. **不要公开分发 APK**（见 §6）。
6. 造测试数据后必须删干净：`del:<txnId>` / `delcap:<id>`，并复核 `txnCount` / `balances`。
